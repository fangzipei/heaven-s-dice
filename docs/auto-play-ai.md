# 自动对局 AI（v2）

文件：`tools/auto-play.mjs`（旧版保留在 `tools/auto-play-greedy.mjs` 方便对比）

```bash
node tools/auto-play.mjs --runs=1000 --seed=20261027
node tools/auto-play.mjs --runs=1 --seed=7 --trace     # 逐关打印构筑
node tools/auto-play.mjs --runs=200 --risk=0.03        # 风险偏好，默认 0
```

## 旧版为什么笨

旧 bot 只做两件事：

1. `bestSelection` 取当前最高分；
2. 用 `totalContinue >= totalReroll` 这种没有含义的比较决定继续还是重投。

它没有「这一手值不值得冒险」的概念，也没有目标意识。300 局基准：平均终点 **2.5 关**，平均掷空 7.4 次。

## 新模型：直接算「清关概率」

这个博弈的核心不是得分高低，而是：

- **计分并继续**：不花重投，但整轮分数继续暴露在掷空风险里；
- **计分并重投**：花一次重投，把本轮分数锁死，骰子全部回杯。

所以每一步都在问：*继续掷，和花一次重投锁住，哪个更容易过关？*

实现分三层：

### 1. 精确的掷骰分布

骰子只有 1–7 颗。按**多重集**枚举所有结果（6 颗只有 462 种计数组合），用 `bestSelection` 求出该组合的最优取分与消耗骰数，再用多项式系数加权。得到 `(得分, 消耗骰数) → 概率`，没有任何采样噪声。

### 2. 动态规划

状态是 `(还要掷几颗骰子, 剩余重投, 还差多少分)`：

```text
V(n, r, gap) = Σ 概率 × max(
    继续: V(剩余骰子, r, gap - 得分),
    锁分: V(6, r - 1, gap - 得分)
)
```

- 掷空 → 本轮分数清零，贡献 0；
- 全骰（消耗 0 颗）→ 免费重掷 6 颗；
- `gap <= 0` → 1（这关过了）。

状态按 50 分一档离散，全局缓存，同一进程内所有局共享。

### 3. 候选选择 + Boss 规则

- 候选不只取最高分：还会试「少选一颗骰子」，用多一颗可重掷的骰子换更高的清关概率；
- 通过 `currentScoringOptions()` 拿到当前 Boss 的计分口径（例如双六赌徒只认 2/6、成双之忌允许对子），分布按口径分桶缓存——这是旧版完全没有的；
- 每个候选都会用引擎的 `getScorePreview` 复核，避免和真实规则脱节。

## 从通关玩家身上校准的部分

拉了 230 局线上记录，其中 35 局通关（峰值 ≤25），统计他们的行为：

**动作偏好**（4348 次决策）：

| 动作 | 占比 |
|---|---:|
| 计分并重投（锁分） | 63% |
| 计分并继续（免费续投） | 32% |
| 计分并结算 | 5% |

**构筑规模**：平均买 **5.9 枚骰子** 和 **13.2 件物品**。

**买得最多的骰子**：连记、衡心、末路、商旅、阴阳、壹面。
**买得最多的物品**：烈酒、幸运粉、加注契约、三环坠、镀金袖扣、夹层行囊。

据此调整了：

- 骰子估值表（`DIE_VALUE`）直接用此前分析的「单骰贡献」倍数；
- 物品估值表（`ITEM_VALUE`）按通关玩家的购买频次排序；
- 道具时机：烈酒在开局用（整关 +1 重投），猎人印记在首次计分前用，赌徒护符/加注契约开局用；
- 商店只买「比最弱骰子强 0.3 以上」的骰子，避免把银币花在劣质骰上。

> 一个反直觉的结果：把 bot 强行往「63% 锁分」校准反而更差（9.9 → 8.9 关）。通关玩家锁分多，是因为他们的骰子质量更高、手牌更大；同样的比例套在弱构筑上就是过早放弃。所以最终默认 `--risk=0`，让 DP 自己决定。

## 基准（300 局，同一随机种子）

| 指标 | 旧 AI | 新 AI |
|---|---:|---:|
| 平均终点 | 2.5 关 | **9.9 关** |
| 通关率 | 0% | **1.3%** |
| 平均掷空 | 7.4 | **4.2** |
| 平均投掷 | 20.3 | 50.0 |
| 耗时 | <1 s | ~25 s |

单局最好能到 19 关；主要断层在 **第 10→11 关**（Boss 关，通过率从 ~55% 掉到 ~25%）和 **第 20 关**（目标从 8407 跳到 14102）。

## 和真人的差距

真人通关玩家平均峰值 24 关，新 bot 只有 9.9。差距主要不在算路，而在：

1. **构筑经济**：bot 平均剩 384 银币花不出去，商店格子有限；真人会攒出 6 枚骰子 + 13 件物品的滚雪球。
2. **Boss 关的策略**：目前只把 Boss 的计分口径喂给分布，没有针对「少一次重投」「分数税」这类一次性效果做专门规划。
3. **道具组合**：重铸器、货架类物品的联动没有建模。

## 下一步建议

- 把 DP 扩到「事件」层：Boss 效果、道具、桶效果作为状态维度；
- 商店用蒙特卡洛评估「买这件物品后 3 关的通过率」，而不是静态估值；
- 给每关单独统计通过率，用真人数据做逐关校准，而不是只看全局终点。
